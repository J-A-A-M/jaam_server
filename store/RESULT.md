# Результат: інтернет-магазин JAAM

Реалізовано згідно `store/task.MD`. Окремий Docker-мікросервіс у стилі проєкту
(Starlette, env-конфіг, мережа `jaam`, `redeploy_*.sh`, nginx-блок).

## Стек і рішення

| Аспект | Рішення |
|---|---|
| Веб-фреймворк | Starlette + uvicorn (як `web_server`) |
| Дизайн | Перевикористано тему JAAM (dark/light, CSS-змінні, перемикач через cookie) — `app/static/store.css` + `app/templates/base.html` |
| БД | SQLAlchemy ORM. SQLite за замовчуванням, перехід на іншу SQL-базу — через `DATABASE_URL` (моделі не залежать від діалекту) |
| Шаблони | Jinja2, модульний пакет `app/` |
| Сесії/кошик | `SessionMiddleware` (підписаний cookie); кошик зберігається в cookie-сесії |
| Паролі | `pbkdf2_hmac` (stdlib, без зовнішніх залежностей) |
| Оплата | До рівня кошика: форма доставки + кнопка «Оплатити» → замовлення у статусі «нове». Реальної оплати немає (за умовою) |

## Архітектура (контракт)

Ядро (`app/core.py`, `app/models.py`, `app/db.py`) — єдине джерело правди:

- **Розрахунок ціни** рахується на сервері з БД (`price_cart`), ніколи не з cookie:
  `ціна = base_price + Σ(ціна вибраних значень модифікацій)`, × кількість.
- **State-machine flow** (`available_transitions` / `move_order` / `cancel_order`):
  кнопки переходу = дозволені переходи з поточного статусу + завжди «скасоване»
  (якщо статус не термінальний).
- **Знімки** даних товару/ціни в позиціях замовлення — редагування каталогу
  не змінює історичні замовлення.

Route-модулі імпортують ці хелпери, кожен експортує `routes: list[Route]`,
`main.py` їх збирає.

## Структура

```
store/
  app/
    config.py          # env-конфіг
    db.py              # engine, сесії, init_db + ідемпотентний сід фіксованих статусів
    models.py          # ORM-моделі
    security.py        # хешування паролів
    core.py            # auth, кошик, ціна, flow, ключі (КОНТРАКТ)
    templating.py      # Jinja2 + render()
    main.py            # збірка Starlette
    seed_demo.py       # демо-каталог для тестування
    routes/
      storefront.py    # юзер: каталог, товар, кошик, checkout, реєстрація, кабінет
      admin_system.py  # дашборд, /become, керування адмінами, ключі
      admin_catalog.py # редактори: розділи, модифікації, товари
      admin_orders.py  # редактор замовлень + редактор статусів/flow
    templates/         # base.html, admin/_base.html, storefront/*, admin/*
    static/store.css
  data/nova_poshta_branches.json   # заглушка відділень НП
  Dockerfile
  requirements.txt
  redeploy_store.sh    # (у корені deploy/)
  nginx_store.conf
  README.md
```

## Фото, карусель, стікери, знижки на товар

- ✅ Єдина картка товару (`storefront/_product_card.html`) — однакова на головній і в розділах: назва → фото/карусель (на всю ширину) → короткий опис → ціна → кнопка
- ✅ Завантаження кількох фото товару (сторінка редагування); кілька фото → карусель (vanilla JS/CSS). Зберігання — `UPLOAD_DIR` (на volume `/data/uploads`), роздача через `/media`
  - Безпека: імʼя генерується (uuid, не довіряємо клієнтському → path traversal), whitelist розширення + content-type, ліміт розміру (`MAX_IMAGE_BYTES`, 8 МБ)
- ✅ Стікери (`/admin/stickers`): назва + кольори фону/тексту; призначення на сторінці редагування товару; показ бейджів у картці й на сторінці товару
- ✅ Знижки на товар (`/admin/product-discounts`): окремий розділ CRUD, призначення товарам (M2M)
  - тип **% або фіксована сума**; **область дії**: лише базова ціна або вся (з модифікаціями)
  - **діє з** (`starts_at`, порожнє = відразу) та **термін дії** (`expires_at`, порожнє = безстроково)
  - **ліміт замовлень** (0 = необмежено; вичерпання → знижка вимикається)
  - при активній знижці ціна показується як «активована знижка» (стара закреслена + нова) — у каталозі, на картці, сторінці товару (JS), у кошику
  - чекбокси **сумувати з акаунтною знижкою** / **сумувати з промокодом**
  - **стікер на період дії** (`sticker_id`): обраний стікер автоматично показується на товарах знижки, лише поки знижка діє (`core.effective_stickers` + Jinja-фільтр `stickers`)
  - **eligible-portion**: позиція без знижки на товар завжди приймає акаунтну/код-знижку; позиція зі знижкою — лише якщо дозволено відповідним прапорцем stack
  - валідність знижки — `core.product_discount_valid` (активна + у межах дат + ліміт не вичерпано)
- ✅ Стікери накладаються на фото поверх (overlay, правий верхній кут → вліво, `flex-direction: row-reverse`); без фото — звичайним рядком
- ✅ Розрахунок — у `core` (ЄДИНЕ ДЖЕРЕЛО ПРАВДИ): знижка на товар рахується в `price_cart_item` (best-discount: макс. зменшення, нічия → min id); `compute_discount` працює з детальними позиціями та накладає акаунтну/код-знижку лише на придатні позиції (eligible-portion за прапорцями stack)
  - кілька активних знижок на товар → береться найвигідніша
  - знімок у замовленні: `subtotal` (до знижок), `product_discount_amount`, `discount_amount`, `total_price`
  - перевірено: кошик == `/checkout/preview` == створене замовлення для комбо (товар+акаунт) і (товар+код), no-stack і stack

## Міграції схеми (важливо для деплою)

`db._ensure_columns()` ідемпотентно додає нові колонки до наявних таблиць (`create_all` створює лише відсутні таблиці, не колонки). Виконується раз на старті. Додані колонки: `orders.product_discount_amount`, `product_discounts.starts_at`, `product_discounts.sticker_id`, `order_statuses.role|color|text_color`. SQLite ALTER ADD COLUMN з простим типом (без FK).

## Деплой

```bash
./redeploy_store.sh -mk "<майстер-ключ>" -ss "<session-secret>"
```
